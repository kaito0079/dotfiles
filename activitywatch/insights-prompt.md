標準入力で渡す JSON は、直近の作業記録を aw-collect.py で集計したもの。
これをもとに、繰り返している作業をショートカットやコマンドにする案を出してほしい。

## JSON の中身

- `window`: アプリとウィンドウタイトルの利用時間・訪問回数、アプリ切り替えの 2 連・3 連の回数
- `web`: ドメインごとの利用時間、よく開くページ、ドメイン間の行き来 (null ならブラウザの記録なし)
- `shell`: 自分で打ったコマンドの回数、先頭 2 語の回数、連続して打ったコマンドの並び、
  cmux ワークスペースごとの内訳 (null なら記録なし)
- `claude`: Claude Code のセッションごとの作業時間・ディレクトリ・ブランチ、最近の依頼文、
  スラッシュコマンド、ツールの利用回数、Claude が実行した Bash コマンドの回数と並び
- `slack`: Slack のチャンネル (`channel`)・DM (`dm`)・画面 (`view`: アクティビティなど) ごとの訪問回数と滞在時間
- `switches`: アプリの切り替え先ごとの手段の内訳 (null なら記録なし。`since` より前の切り替えは含まない)。
  手段は `shortcut` (直前の修飾キー付きの組み合わせ。`shortcuts_used` に組み合わせ名)、
  `raycast` (Raycast を開いてから選んだ。`raycast_median_sec` は選ぶまでの秒数の中央値)、
  `mouse` (`mouse_places` に dock / menubar / window)、`cmdtab`、`unknown` (通知やリンクから開いたなど)
- `combos`: アプリごとの修飾キー付きの組み合わせの回数 (切り替え以外の操作も含む)
- `window` と `web` は離席していない時間に限った値
- コマンドの並びはタブ (cmux のサーフェス) や Claude のセッションごとに数えており、
  並行して進めている別の作業が混ざった並びではない
- ターミナルでの作業の多くは Claude に任せているため、`shell` は少なく `claude` が多いのが普通

## 進め方

1. カレントディレクトリは dotfiles リポジトリ。提案する前に、既にある仕組みを Read / Grep で確認する。
   - `hammerspoon/.hammerspoon/` (ホットキー・ウィンドウ配置)
   - `zsh/aliases.zsh`、`zsh/.config/zsh/` (エイリアス・関数・キーバインド)
   - `raycast/`、`claude/.claude/settings.json` (許可リスト・フック)
   - `$HOME/work/github.com/kaito0079/claude-plugins/plugins/*/skills/`、`.../agents/` (Claude のスキル・エージェント。
     プラグインとして配布している別リポジトリ。読めなければ省略してよい)
   既にショートカットがある作業は、案に含めず「既存の手段を使っていない可能性」として別に挙げる。
   Raycast のホットキーは Raycast 内に暗号化して保存されていて読めない。代わりに `switches` から判断する。
   - `shortcuts_used` に出ている組み合わせは、そのアプリへのショートカットとして登録済みで使えている
   - ショートカットが使われているのに `raycast` / `mouse` の割合が高いアプリは「登録済みだが使えていない」
   - ショートカットが一度も使われていないアプリは「未登録の可能性」。Raycast か hammerspoon での割り当てを提案する
   - `switches` が null か件数が少ないときは判断できないので、「Raycast で登録済みなら、使えていない可能性」と添える
3. Slack は `slack` の訪問回数が多いチャンネル・DM を、Raycast のクイックリンクとして登録する候補に挙げる。
   Slack 内の移動手段は記録していないため、`combos` の Slack の `⌘k` の回数を「検索して開いている」目安にする。
   リンクは Slack でチャンネル名を右クリック →「リンクをコピー」で取れることを添える。
2. 効果が大きい順に最大 5 件を提案する。効果は「回数 × 1 回あたり省ける時間」で見積もる。
   自分の手の操作 (`window` / `web` / `shell`) と、Claude への頼み方 (`claude`) の両方から探す。
   後者は、同じ趣旨の依頼の繰り返しをスラッシュコマンドやスキルにする、毎回実行している
   前準備を CLAUDE.md やフックにまとめる、などを想定する。
4. データが少なすぎて傾向が読めないときは、無理に案を作らずその旨だけを書く。

## 出力

Markdown だけを出力する (前置きや締めの挨拶は不要)。

```
# 繰り返し作業の分析 (<期間>)

## 概要
<期間中の作業傾向を 3 行以内で>

## 提案
### 1. <案の名前>
- 根拠: <JSON の数値をそのまま引用>
- 手段: hammerspoon / zsh 関数 / エイリアス / Raycast / Claude のスキル・コマンド / CLAUDE.md / フック / その他
- 置き場所: <リポジトリ内のファイルパス>
- 実装例:
  <そのまま貼れるコード>
- 見積もり: <週あたりの削減時間>

## 既存の手段を使っていない可能性
<該当なしなら省略>
```

- 案はそれぞれ単体で完結させ、既存の命名・書き方に合わせる。
- ファイルは編集しない。採用するかどうかは読んだ人が決める。
